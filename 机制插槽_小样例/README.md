# 机制插槽 MOEA 小样例

2026-10-13。目的：用最小代价检验两个想法，帮助决定后续往哪走。
- **想法一**：把 MOEA 拆成机制，外层搜索去拼机制（AutoMOEA 式）。
- **想法二**：LLM 不写整个算子，只替代某个机制里的一小段规则。

对应 `前沿调研_2024-2026/02_多目标机制专题/moea_mechanisms_report.md` 中的切入点 A（劣解 archive）、C（步长分布）、E（LLM 结构化设计）。

## 文件

| 文件 | 作用 |
|---|---|
| `slot_moea.py` | 骨架 + 3 个插槽（步长 / 劣解 archive / 精英复用），numpy-only；含 ZDT1-4,6、DTLZ1-2 和 IGD |
| `experiment.py` → `results.csv` | 全因子：4 步长 × IA 开关 × 复用开关 × 7 问题 × 15 种子（1680 次运行，双核约 7 分钟） |
| `analyze.py` → `summary.md` | 排名、Wilcoxon、log-IGD 方差分解（主效应 vs 交互） |
| `llm_slot_prompt.md` | 步长插槽的窄接口提示词：LLM 只写 `rule(state, n, rng) -> F` |
| `llm_rules/*.py` | 3 条按该提示词一次生成的候选规则（Claude 生成，**没有外层迭代**） |
| `evaluate_rules.py` → `rules_summary.md` | 把 `llm_rules/` 下的规则放进同一骨架，与内置规则对比 |
| `headroom.py` → `headroom_summary.md` | 5 万次评价：4 种静态配置 vs 4 种简单在线调度（`inf`/`reuse` 现在可以传入 `state -> 概率` 的函数） |

复现：`python experiment.py 15 2 && python analyze.py && python evaluate_rules.py 10 1 1 2`

## 实验设定与局限

- 骨架为 DE/rand/1/bin + 多项式变异 + NSGA-II 选择；N=100，1 万次评价；IGD 在外部 archive 上计算，所有配置一致。
- **ZDT4、DTLZ1 在 1 万次评价下所有配置都没收敛**（IGD 达 3–20），这两行只能看相对趋势，结论以 ZDT1-3、DTLZ2 为主。ZDT6 上所有配置几乎相同，差异属于噪声。
- 只有 3 个插槽、16 个组合，比 AutoMOEA 的设计空间小得多；环境选择本身还没做成插槽。

## 发现

1. **劣解 archive + 精英复用是最强的信号**（即切入点 A）。在 ZDT1/2/3 上，最佳组合比基线 IGD 低 6–19 倍（p≈7e-4，15 对配对样本）。去掉其中任一机制，效果都明显变差。但在多峰的 ZDT4、DTLZ1 上，劣解 archive 反而略有坏处（见 `summary.md` 第 4 节），说明它的收益依赖问题类型。
2. **机制之间几乎可加。** 在 log-IGD 上，交互项只占已解释方差的 1–7%（ZDT6 的 32% 是噪声）。这意味着在这个空间里，"每个插槽各自选最好"已接近"最好的组合"，**外层组合搜索（想法一）能多拿到的东西很少**。变化主要来自"问题 × 机制"：每个问题各选最优配置，相比全局最好的单一配置还能再好 1.0–1.6 倍。
3. **一次生成的 LLM 规则没有超过免调参的幂律步长。** `bimodal_explore` 平均排名第一（2.43 对 heavy 的 2.86），但这个优势主要来自 ZDT4/ZDT6 这类噪声大的行；在 ZDT1-3 上，幂律步长仍然最好。手写的状态规则 `state` 在全因子实验中平均排名垫底。也就是说，"让 LLM 凭空写一个步长公式"在纯数值基准上价值有限。

## 补充：5 万次评价的结果（修正了上面的第 1 点）

- 在 ZDT1–3 上，所有配置都已收敛，彼此差距 < 15%。1 万次评价时看到的 6–19 倍差距，主要反映的是**收敛速度**。
- 在多峰问题上，**劣解 archive 明显有害**：ZDT4 上 IGD 变差约 2 倍，DTLZ1 上约 7 倍。**只开精英复用**则是最好的：ZDT4 上 0.40，而都关为 5.99；DTLZ1 上 0.031，而都关为 0.18。这和 Ren 2026（archive 复用）以及 Zheng 2024（随机种群更新在多目标上常常无益）一致。
- 每个问题选对静态配置，相比全局最佳静态配置可提升 11 倍（ZDT4）和 29 倍（DTLZ1），说明提升空间很大。但 4 种简单调度只拿到了很小一部分：它们把 IA 和 RE 绑在一起开关，无法得到"只复用"的配置，下一轮需要拆开。
- 文献核对和可行性判断见 `前沿调研_2024-2026/04_机制在线调度_可行性评估.md`。

## 补充 2：特征可分性检验（`separability.py`，16 个实例，约 12 分钟）

- 只看前 20% 预算，"停滞代数占比"一个特征就能完全区分"劣解有害"的实例（AUC = 1.00，留一族准确率 100%）。
- 但在 5 万次评价下，"始终关掉劣解 archive"已经等于上界，在线调度没有提升空间。只有在 1 万次评价这类小预算下才有真实取舍（最好固定策略距上界约 11%）。
- 详见 `separability_summary.md`，以及调研报告 04 的第 6 节。新增实例定义在 `instances.py`。

## 由此建议的切入点（写于可分性检验之前，结论见上面的补充 2）

**"状态条件化的机制调度"**：不再静态拼装机制，而是让一个窄接口控制器根据运行状态决定**用不用、用多少**某个机制。

- **输入**：`succ`、`rank1_frac`、`stall`、`arch_frac` 等，再加 archive 的 HV 增量。
- **输出**：步长分布参数、劣解 archive 的使用概率 `p_IA`、精英复用概率 `p_RE`。
- **生成方式**：由 LLM 根据历史运行日志离线写出规则，通过 EoH 式外层迭代进行评估、反馈和改写；最终冻结规则，运行时不再调用 LLM（类似 MOEA/D-LO、Code World Models 的思路）。

依据是发现 2：方差主要来自"问题 × 机制"，而非"机制 × 机制"。静态组合抓不到这部分差异，状态条件化的调度有可能抓到。

## 下一步（按顺序）

1. **补齐让结论可信的条件**：评价预算提到 5 万、加入 WFG1–9、种子数增至 30；把 IA 的使用方式做成连续参数 `p_IA` 后重跑全因子实验，确认发现 1 和 2 是否仍然成立。
2. **先做"非 LLM"的状态调度基线**：例如根据 `stall` 切换 `p_IA`。如果它已经能接近"每问题选最优"的上界，就说明调度这条路可行；如果做不到，再引入 LLM。
3. **为窄接口加入外层迭代**：把 `evaluate_rules.py` 的排名作为反馈，让 LLM 改写规则，看是否能稳定超过幂律步长和 SHADE。
4. **移植到 `MOEA_serial_full_cpp`**，在 247 个算法上做"插入 IA + 复用"的大规模验证，并加入 DLBP 和 MOJSP。
