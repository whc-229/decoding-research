# 实验 2：E 组失败原因、C/D 表示指标、解码方式基因（2026-10-15）

## 结论

1. **E 组输的原因是"规则离好解太远"，和机器人类型无关。**
   - 原来的推测不成立：E01、E02 只有一种机器人类型。
   - 把好解相对规则需要偏离的次数除以偏离槽数 K，记为 dev/K：
     - dec6b 显著变差的 4 个实例（原请求、E01、E02、H04），dev/K 都在 0.70～0.83；
     - dev/K 在 0.10～0.55 的 7 个实例，dec6b 全部持平或更好。
   - 在需要偏离的 12 个实例上，dev/K 与 HV 差值（dec6b − dec5）的秩相关 ρ = −0.60，p = 0.04。另外 4 个实例只按规则排就能得到资源最少层的解，所以没计入。
   - 以 E01 为例：只按规则排会多用 1 台机器人；资源最少层的好解需要偏离 22 次，K = 27，而随机初始化平均只激活约 11 个槽。
   - 结论：稀疏偏离这个偏置只在好解离规则近时成立，这和 Rothlauf"有偏表示不稳健"的结论一致。
2. **C、D 场景的表示指标补齐了，结论和原请求、B 一致。**
   - dec6 让随机基因到达资源下界的概率从 0.004～0.014 升到 0.22～0.24；
   - 多项式变异下的级联比例（精英基底）从约 0.58 降到 0.22～0.37。
3. **解码方式基因：选择确实学会了避开错误的偏置，但好偏置只用上了一部分，整体比 dec5 更稳，但不是全面更好。**
   - **选择的方向基本对：** 最终档案里选 dec6b 的比例：
     - E01、E02 只有 6%～7%（非支配解里为 0），原请求 18%，这些都是 dec6b 输的实例；
     - B、D 为 54%～58%（非支配解里 72%～77%），M 组为 38%～72%，这些是 dec6b 赢的实例。
     - 但在全部 12 个实例上，选择比例与 dev/K 的秩相关只有 −0.33（p = 0.29），只有两端的实例分得清楚。
   - **和 dec5 比：**
     - 显著更好：B 和 M01 的下界层均衡度（B 从 2.29 倍最优降到 2.10 倍，p = 0.013）；
     - 显著更差：只有 M03 的 HV（p = 0.01）；
     - 其余 13 个实例无显著差别；
     - 对照：dec6b 单独使用时，有 4 个实例显著变差。
   - **和 dec6b 在它擅长的实例上比：** 自适应版本的提升被稀释了。例如 B 场景，自适应是 2.10 倍最优，dec6b 是 1.68 倍。
   - **速度：** 除原请求外，单次耗时和 dec5 基本相同；原请求是 16.7 s 对 7.4 s，因为 dec6 部分在这个场景上本来就慢。

**对主线的含义：**
- 理论分析这条线已经比较完整：性能由偏置决定（实验 0）；偏置有利与否取决于规则离好解有多远（实验 1、2）；规则离得远时，换一种偏置就会输。这些都可以用可测量的量（初始供给、dev/K）讲清楚。
- 方法上，"解码方式基因"做到了不吃亏，但收益有限。原因是选择压力要等种群收敛到一定程度才起作用，在 465 次评价的小预算下来不及充分偏向好的解码。
- 下一步更有希望的两个方向：
  1. **先估计，再选择：** 用便宜的 dev/K 或初始供给预估规则离好解有多远，直接选解码。缺点是 dev/K 要先有一个好解才能算，需要找一个不依赖好解的代理量，例如只按规则排出来的解比下界多几个资源、规则解的均衡度。
  2. **让偏离数自适应：** 不在 dec5 和 dec6 之间二选一，而是让 K（或者偏离启用的概率）随实例调整。规则离好解远，就自动多给偏离。dec5 可以看成偏离数等于班次数的极端情况，所以这其实是把两种解码统一成"偏离密度"一个连续参数。这比二选一更自然，也是一个新的表示设计点。LLM 可以在这里根据实例特征给出偏离密度或规则本身。

## 1. 自适应版本的设计（`paiban_dec7`，Python `sde.decode7`）

- 编码与 dec5、dec6 相同，只多用了末位基因：x[Nvar−1] < 0.5 按 dec5 解码，≥ 0.5 按 dec6b 解码。dec5 和 dec6 都不读这一位，所以不需要改编码长度。
- 交叉会混合两种解码的个体，这时基因的含义不一致。这是这类"解码方式基因"做法的固有代价，没有专门处理。
- C++ 与 Python 逐解核对：168 条，覆盖 4 个场景和实例族全部 12 个实例，全部一致。

## 3. 局限

- 实例族的 dev/K 是用 dec5 一次运行的最好解算的，会偏向 dec5 能找到的解；H03 的 dev/K = 1.06，但那个解本身没到达下界，参考价值低。
- 实例族每组只有 8 次运行，显著性检验的功效有限。
- 自适应版本的选择阈值 0.5 和 dec6b 的参数都没有调。
- 所有 MOEA 对照都在同一台机器上运行，但不是同一批：dec5 和 dec6b 的主场景数据来自实验 0、1，计时可能受当时机器负载影响。
