# 实验 3：偏离密度——按实例选择解码的自由度（2026-10-15）

## 结论

1. **最合适的偏离密度确实因实例而异，按实例选择有实际收益。**
   - 把"稀疏偏离（偏离槽数 K = 0.1 / 0.25 / 0.5 × 班次上界）"和"逐班基因（dec5）"看成同一个密度参数的四档。在 16 个实例上：
     - 7 个实例 dec5 最好：原请求、C、E01、E02、H02、H04、M03；
     - 8 个实例某一档稀疏偏离最好：B、D、H01、H03、M01、M02、M04、M05；
     - E03 各档持平。
   - 选档的收益（平均归一化 HV，dec5 = 0.854）：

     | 选法 | 相对 dec5 | 说明 |
     |---|---|---|
     | 事后选最好档（oracle） | +0.079 | 用同一批运行既选档又评价，偏乐观 |
     | oracle 交叉验证版 | **+0.044** | 一半运行选档、另一半评价，是比较现实的上限 |
     | 每档先试跑 1 次再选 | +0.014 | 代价是每档多跑 1 次 |
     | 单用任何一档 | −0.040 ~ −0.131 | 单用 dec5 即 0 |

2. **不能让密度在运行中自己调整。**
   - 把启用槽数编进基因（K=自适应），进化后启用比例都缩到 0.13～0.15，平均 HV −0.136，6 个实例显著更差。
   - 实验 2 的解码方式基因（dec7）也只做到持平（−0.007）。
   - 两次结果一致：在 465 次评价的小预算下，靠选择压力调编码太短视，选档必须在运行之前做。
3. **逐班阈值式的密度编码（dec8）失败了，原因是编码和变异算子不配合。**
   - dec8 是"每班一个基因，超过阈值 1 − d 才偏离"。d = 0.05～0.2 的各档都显著差于 dec5，在 4～9 个实例上显著更差。
   - 原因：多项式变异（η = 20）每次只把基因挪动几个百分点，阈值附近以外的基因几乎不可能被变到阈值以上。偏离在初始化后基本冻住，搜索改不动它们。
   - 用位置基因决定偏离落在哪一班（dec6 的做法）就没有这个问题。这是一个"表示要和算子一起设计"的具体例子，可以写进论文。
4. **便宜的随机样本特征选不对档。**
   - 按初始供给（随机基因 ≤ 下界+1 的比例）选：几乎总是选 K = 0.1，平均 HV −0.090。K = 0.1 的初始供给最高，但它留给搜索的自由度太少。
   - 按随机样本里的最好解选：−0.032。
   - 这修正了实验 0 的结论：自由度相近的解码之间，初始供给能解释排序；但自由度不同的解码之间，还有一个"初始离好解近"和"有没有改进空间"之间的权衡，初始供给只反映前者。
5. **LLM 选档的脚本已经写好，等你填好接口后运行。** 它只能从四档里选，选完直接用上面同一批运行结果离线评价，和 oracle、交叉验证版、试跑这几种选法对比。

**对主线的含义：**
- 论文的分析部分现在形成了一条完整的链：
  1. 性能由偏置决定（实验 0）；
  2. 偏置好不好取决于规则离好解有多远（实验 1、2）；
  3. 偏置要和自由度一起权衡，最合适的密度因实例而异，选对能带来约 +0.04 的 HV（交叉验证版）；
  4. 运行中自适应（解码方式基因、启用槽数基因）在小预算下都失败；
  5. 便宜的随机样本特征也选不对。
- 由此，方法上真正要解决的是：**运行之前，怎样为实例选对编码的偏置和自由度。** 这是一个"表示选择"问题，正好是 LLM（读实例描述，用领域知识判断）或者学习型选择器的用武之地。
- 下一步建议：
  1. 先跑 LLM 选档（两种提示），看能否超过试跑（+0.014），接近交叉验证上限（+0.044）。
  2. 用 `tools/gen_family.py` 再生成 50～100 个实例，训练一个简单的选择器（实例参数 + 便宜特征 → 选档），做留一实例验证，作为 LLM 的对照。16 个实例太少，任何选择器的结论都不可靠。
  3. 也可以考虑运行中按预算分配的方式，例如多臂老虎机在几种解码之间分配评价次数。它和解码方式基因不同，不依赖遗传传递，可能比试跑更省。

## 1. 编码

| 名称 | 做法 | 程序 |
|---|---|---|
| dec8（偏离密度） | 每班一个基因 x[i]；x[i] ≥ 1 − d 时偏离，否则按规则。新开类型由该班基因决定 | `paiban_dec8 --dev-density d`；不给 d 时由末位基因自适应 |
| dec9（可调槽数） | 即 dec6b，偏离槽数 K = f × 班次上界，f ≤ 0.5 | `paiban_dec9 --slot-frac f`；`--slot-adapt` 时启用槽数 = ⌈K × 末位基因⌉ |

C++ 与 Python 逐解核对：dec8 共 384 条（自适应、d=0.05、d=0.3 三种设置），dec9 共 288 条（f=0.1、0.5、0.5+自适应），全部一致。

## 2. 实验设置

- C++，NSGA2，种群 30 × 10 代，约 465 次评价。
- 新跑的各档：4 个场景各 12 次，实例族 12 个实例各 6 次。
- dec5、dec7、K=0.25（dec6b）沿用实验 1、2 在同一台机器上的运行：4 个场景各 20 次，实例族各 8 次。
- HV 在每个实例内用所有臂的解统一归一化。
- 便宜特征：纯规则解（比下界多几个资源、均衡度）；每档 100 个均匀随机基因的初始供给与最好解。

完整表格见 `out9/report_arms.md`。

## 3. 局限

- 只有 16 个实例，选择器和 LLM 的评价都只能算初步结论。
- 交叉验证版 oracle 在实例族上每个实例只有 6～8 次运行，方差较大。
- 纯规则解在多类型实例上新开机器人一律用 0 型，所以 M01、M02、H03 的"规则比下界多几个资源"偏大，不完全反映规则本身的好坏。
- E01、E02、E03、H01 的 dec8 初始供给特征没有算完（太慢），但不影响结论：dec8 本身已被否定，选档评价只用 dec9 的特征。

## 4. LLM 选档怎么跑

1. 填好 `实验0_表示分析/llm_config.json` 里的 `api_base`、`api_key`、`model`。接口按 OpenAI 兼容的 `/chat/completions` 调用。
2. 在 `实验0_表示分析/` 下运行：
   ```
   python llm_choose_d.py --mode params            # 只给实例参数
   python llm_choose_d.py --mode params+features   # 再给便宜特征
   python eval_arms.py out9/runs out9 out9/report_arms.md out9/llm_choice_params.json out9/llm_choice_params+features.json
   ```
3. 每个实例默认采样 5 次，取众数作为选择。中途断了重跑会接着上次的进度继续。加 `--dry-run` 可以只看提示词。
4. 提示词里给了 LLM 一句领域常识（"稀疏适合好解靠近规则的情况，逐班适合需要大量偏离的情况"），但没有给任何运行结果。
