# 规则生成实验（LLM 改写解码器的默认规则）

## 做什么
稀疏偏离编码（K=0.25）里，基因只决定约 25% 的班次，其余班次全由"默认规则"决定，所以默认规则就是搜索的偏置。
实验 3b 里 E 组输给 dec5，原因就是默认规则离好解远。这里让 LLM 写新的默认规则，用进化的方式迭代：

1. 初始：默认规则 + LLM 按 5 种不同思路各写 1 条（维修错峰、异构类型、出发时机、均衡、容量预判）；
2. 每代 4 个后代：改进（2 个）、换思路（1 个）、组合（1 个）；出错的代码让 LLM 修一次；
3. 保留得分最高的 6 条进入下一代，共 12 代，约 55 次 LLM 调用。

**打分（代理指标）**：15 个训练实例（新实例族中 E/H/M 各 5 个），每个实例用同一批 64 个随机基因 + 3 个不偏离基因解码，
算这些排班的归一化 HV。实验 3b 表明"随机样本最好解"能预测 MOEA 的表现，所以用它代替真正跑 MOEA，每条规则只需几十秒。
**测试集（其余 47 个实例）在生成过程中完全不用**，规则确定后再用 MOEA 验证。

**两种反馈（消融）**：
- `full`：把理论上的诊断量喂回 LLM —— 不偏离时比下界多几个资源（规则距离）、均衡度、随机样本最好解、可行率等，按组给出；
- `score`：只告诉 LLM 总分（相当于 EoH 一类方法的做法）。
两者对比可以说明"理论指导的反馈"有没有用，这是和已有 LLM 生成启发式工作的主要区别。

## 怎么跑（在 Windows 上，`实验0_表示分析\rulegen\` 目录下）
```
python rulegen.py --dry-run                 # 先看一眼提示词（会先花约 1 分钟算默认规则的基准）
python rulegen.py                           # 主实验，结果在 out\full\
python rulegen.py --feedback score          # 消融，结果在 out\score\
```
- 接口配置沿用上一级的 `llm_config.json`。
- 默认用"CPU 核数 − 1"个进程评价规则；电脑卡的话加 `--procs 4`。
- 断了（包括余额不足报 402）重新运行同一条命令即可从断点继续。余额、密钥这类错误会直接停下并提示，不会无限重试。
- 两个实验可以先后跑，也可以开两个窗口同时跑（会抢 CPU，慢一些）。
- 跑完把 `out\full\` 和 `out\score\` 告诉我，我来做测试集上的 MOEA 验证。

## 安全
LLM 写的代码只在受限环境里执行：只能用 `math`，禁止 import、文件读写、反射、下划线开头的属性和 while 循环；
超时的规则会被终止并记为失败。所有提示词和回复都记录在 `out\<tag>\llm_log.jsonl`。

## 文件
- `ruledec.py`：可替换默认规则的稀疏偏离解码；默认规则下与 dec9（C++ paiban_dec9）逐解相同（`check_ruledec.py`，168 条全部一致）
- `evalrule.py`：代理打分与诊断
- `rulegen.py`：LLM 进化循环
- `instances.py`：训练/测试划分
- `ga_rule.py`：规则确定后在测试集上跑 MOEA 验证
