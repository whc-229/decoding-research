# 实验 1：规则 + 稀疏偏离编码（dec6）（2026-10-15）

## 结论

1. **dec6 没有全面超过 dec5，好坏取决于实例。** 以 dec6b（改进版）为准，在 16 个实例上和 dec5 比：

   | | 4 个场景 | 实例族 12 个 |
   |---|---|---|
   | HV 显著更好 | B | — |
   | HV 显著更差 | 原请求 | E01、E02、H04 |
   | 下界层均衡度显著更好 | B（2.29 → 1.68 倍最优）、D | M01 |
   | 下界层均衡度显著更差 | 原请求 | E02 |
   | 到达下界 | 4 个场景全部 20/20（dec5 在 B、D 是 17/20） | — |

   其余实例无显著差别。
   - 速度：多数实例上单次耗时是 dec5 的 1.0～1.3 倍，个别实例（原请求、E01、E02、H01）是 1.6～2.4 倍。
2. **局部性确实改善了，但这不是决定性能的因素。**
   - 精英基底的级联比例从 0.48～0.61 降到 0.35～0.39，用 MOEA 实际的多项式变异测量（原请求、B）。
   - 可是原请求的局部性改善最多，性能反而变差。
3. **决定输赢的还是初始供给（偏置落在哪里），和实验 0 的结论一致。**
   - **dec6 占优或有占优趋势的实例，初始供给都大幅上升：**
     - B：随机基因解码到资源下界的概率从 0.007 升到 0.22，随机样本里甚至直接出现了 3.406（最优是 3.386）；
     - M01、M04、M05、H02、H04、M03：这个概率从 ≤ 0.05 升到 0.28～0.64（第一版 dec6；dec6b 因为新开更多，只升到 0.04～0.17）。
   - **dec6 输的实例，初始供给没有提高或者下降了：**
     - 原请求：0.83 → 0.75；
     - E02：0.05 → 0.01；
     - E01：两者都是 0。
   - **H02、H04 是例外：** 初始供给上升了，HV 却更低。原因是 dec6 把搜索集中在资源数最少那一层，丢掉了"多用几台机器人、均衡度好很多"的前沿点（见第 4 条）。
4. **"偏置太集中"会缩小前沿。**
   - 第一版 dec6 中，"新开"偏离受容量预判约束，前沿几乎只剩资源数最少的点。例如 H02：dec5 的前沿有 11:5.8 这样的点，dec6 只有 8:17.1。
   - dec6b 放开了这个约束，并把新开在偏离取值中的占比从 15% 提到 30%。H02、M03 因此不再显著变差，但 E01、E02、H04 仍然更差。

**对主线的含义：**
- 两个实验合起来指向同一件事：在这类顺序构造型解码上，性能主要取决于偏置落在哪里，即好解被多表示的程度。局部性和可达性都是次要的。
- 但没有一种偏置对所有实例都好：
  - dec5 的"逐班基因 + 修复"在原请求、E 组更好；
  - dec6 的"规则 + 稀疏偏离"在 B、D、M 组更好。
- 这正是 Rothlauf 说的"有偏表示不稳健"，也给了论文的方法部分一个更站得住的方向：不去找一个更好的固定解码，而是**根据实例自适应地选择或组合偏置**。例如：
  - 在个体里加一个"解码方式基因"，让 MOEA 自己在 dec5 和 dec6 之间选择；
  - 或者先用实验 0 的便宜指标（随机基因的初始供给）预判该用哪种解码。
- 这里也是 LLM 最自然的位置：根据实例特征和指标反馈，生成或挑选默认规则与偏离方式。

## 1. dec6 的设计

- **默认规则：** 每班复用出勤最少（出勤相同时剩余工时多）的可用机器人。没有可用机器人时先做回溯修复（同 dec5，窗口 12 班），修复不了才新开，新开类型由一个全局"默认类型基因"决定。
- **基因：** 机器人半段只编码 K = max(4, ⌈0.25·Nmax⌉) 个偏离槽 (p, a)，外加 1 个默认类型基因。
  - a < 0.6：该槽不起作用。
  - a ≥ 0.6：第 int(p·Nmax) 班偏离，u = (a − 0.6)/0.4：
    - u 落在改派区间时，改派给排名第 2～n 的可用机器人；
    - u 落在新开区间时，新开一台对应类型的机器人。
  - 工具基因与原来相同。编码长度也与 dec5 相同，所以可以直接用同一个 MOEA。
- **两个版本：**
  - dec6：改派占偏离取值的 85%，新开受容量预判约束；
  - dec6b：改派占 70%，新开总是执行。dec6b 是看了第一轮结果后改的，见结论第 4 条。
- **可达性：** 精确最优排班相对规则的偏离数为：原请求 13、B 9、C 15、D 9，都在 K 以内。
  - dec6 在原请求和 C 上能精确表示最优解。
  - B、D 和 dec5 一样，被容量预判挡在外面。
- **核对：** C++ `paiban_dec6`、`paiban_dec6b` 与 Python 版 `sde.py` 逐解一致：dec6 共 280 + 56 条，dec6b 共 112 条，覆盖 4 个场景和实例族全部实例。

## 4. 局限

- dec6b 是看了第一轮结果后调整的版本，在同一批实例上评价，有轻微的"在测试集上调参"之嫌。论文里需要另取一批实例做确认。
- 只调整过 K、0.6 的启用阈值、改派占比这三个参数中的一个，其余都没有调。
- E 组输的原因还没有查清。一个推测是：E 组是异构机器人，dec6 只用一个全局默认类型，新开机器人的类型选择不够灵活。这一点没有验证。
